# H53 · Rechazar una botica con motivo

- Historia (Lab06 #59): Como administrador, quiero rechazar una botica indicando el motivo, para que el dueño pueda corregir su registro.
- Criterio de aceptación: No se puede rechazar sin escribir el motivo. El dueño ve el motivo en la web y puede corregir (H7).
- Responsable: Guillermo · Fecha de la prueba: 30/10 y 31/10/2026 · Entorno: admin de Django + web (React, `VITE_USE_MOCK=false`) + API Spring Boot, local, contra Supabase

## Pasos

1. En el admin, rechazar **Botica Nueva Era** sin escribir motivo.
2. Rechazarla con el motivo "La dirección no coincide con la ficha RUC. Corrígela y vuelve a enviar." (30/10, 14:14 y 14:23).
3. En la web, entrar como `lucia@boticompara.nissidev.dev` y abrir **Corregir**.

## Resultado esperado

El rechazo sin motivo no se guarda. Con motivo, la botica queda `RECHAZADO` y el dueño ve el motivo en la web junto con el formulario para corregir.

## Resultado obtenido

1. El formulario no deja guardar sin motivo (además, la BD lo exige con `chk_motivo_rechazo`).
2. La botica queda `RECHAZADO` con el motivo y registrada en el historial (H47).
3. La web muestra "Motivo del rechazo: ..." arriba y el formulario de corrección con los datos de la botica para editarlos y la sección de licencia.

No se reenvió, para dejar a Lucía rechazada para la demo de H7.
